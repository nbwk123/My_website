      GitHub 项目仓库

      为什么要设计个人网页

      WHY

      GOAL 01

      让作品集变成系统，而不是一次性页面。

      网站需要同时承载首页、课程笔记、项目案例、友链和关于信息，并在未来内容增加后仍然保持清晰结构。

      GOAL 02

      让低代码用户也能维护内容。

      通过网站管理器把页面选择、内容编辑、模块插入、预览、构建和部署流程集中起来，减少直接修改代码的压力。

      GOAL 03

      让 AI 协作有清晰判断标准。

      每次修改不只追求“看起来好看”，还要检查定位是否清楚、项目是否可读、交互是否必要、中英文是否一致。

      方法

      • 用 MkDocs 和 Material 搭建稳定的信息结构
      • 用自定义 CSS 和 JavaScript 补充个人化视觉与交互
      • 用中英文目录维护双语内容
      • 用本地管理器降低日常编辑门槛
      • 用 GitHub Pages 完成公开托管

      当前已经完成

      首页作品入口

      首页用大标题、项目卡片堆叠和拖拽切换，让访客一进来就能看到代表作品。

      内容模块化

      课程、项目、友链和关于页面都采用更丰富的模块，而不是只有普通 Markdown 段落。

      可维护功能

      已经加入搜索、中英文切换、浅色 / 深色 / 跟随系统主题，以及 GitHub Pages 发布流程。

      网站管理器

      管理器提供页面选择、新建页面、模块插入、预览、构建和部署入口，是后续低代码维护的基础。

      后续修改方向

      下一步重点： 把管理器从“代码编辑辅助”继续推进到“可视化内容编辑”，让常用模块可以像卡片一样被新增、修改和重排。
